# RGSS 地图查看器实施计划

## 目标

让 RGSS 修改器的迷你地图严格对应游戏地图的实际格子，并能完整查看、缩放、定位和检查事件。地图数据取自运行中的游戏对象，所有事件和玩家标记与地图格分开绘制。

## 交互与显示约定

- 地图宽、高直接使用当前 RGSS 地图的 `width` 和 `height`；每个游戏坐标对应一个独立格子，不做抽样合并。
- 默认缩放为「完整适配」：整张地图宽高都落在弹窗可视区域内。缩放滑块的最小值始终对应完整适配，增大时允许滚动查看细节。
- 参照用户给出的地图截图：深蓝表示不可通行，青蓝表示可通行；事件用带编号的浅色标记，玩家用绿色方块，传送事件用紫色圆环；格线清楚可辨。
- 点击任意格弹出该坐标的操作：传送、事件解释器。没有事件的格子仍可传送，事件解释器在该格没有事件时禁用；同格多个事件时先选事件。
- 事件解释器沿用现有事件页和指令浏览能力。

## 实施阶段

1. **已完成：修复地图数据契约**：移除会缩减格数的抽样；行数据仅表达可通行/不可通行，玩家与事件坐标单独传输；补充可识别的传送事件标记。
2. **已完成：重做地图绘制与缩放**：默认按地图宽高适配弹窗可用宽高；增加滑块控制缩放；加入截图参考的底色、格线和玩家/事件/传送标记。普通 RGSS 与 Pokémon Essentials 两个界面使用相同规则。
3. **已完成：增加格子操作弹窗**：任何格子可选择传送；带事件的格子可选择事件解释器，并支持同格多事件。
4. **已完成代码收尾**：补齐英文/日文界面文案、README 与发布说明。

游戏内人工验收尚未执行；本次没有运行构建或测试。实际游戏中仍需按下方清单检查边界、不同地图尺寸、缩放和事件交互。

## 验收要点

- `width × height` 个逻辑格都可对应到原始坐标，地图边界没有漏格或合并格。
- 小地图初开时整张图全部可见；拖动滑块可连续放大/缩小，回到最小值恢复完整适配。
- 地形色、事件编号、玩家位置、传送点圈选互不覆盖数据，标记不会改变格子的通行颜色。
- 空格可传送；事件格能选事件解释器；多事件格能区分事件。
- VX/VX Ace/XP 的尺寸和边界正确，适用的 Pokémon Essentials 地图仍可显示。
